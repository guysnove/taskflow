# Retrospective — TaskFlow work in Course 2, Chapters 17–21

Course 2, Chapter 22. Format: **Keep / Problem / Try**, then one or two actions, each with an owner.
Everything below happened in this repository's history; links are to the milestone branches.

## Keep (it worked; keep doing it)

- **Tests first found real bugs.** Blank notes were saved as "" instead of null (Ch. 18); titles accepted control characters, so a form post could forge log lines (Ch. 20, F1).
- **Gates in CI.** The coverage gate (Ch. 19), the end-to-end test (Ch. 18) and NuGet audit as an error (Ch. 20) run on every push and every pull request.
- **Small pull requests.** PR #2 (overdue filter) was 4 files; the review question took one test to answer.

## Problem (it hurt)

- **A check that could never fail.** For several chapters CI ran `dotnet list package --vulnerable`, which exits 0 even when it finds a vulnerability (found in Ch. 20, F3).
- **A test that pinned a leak.** An email-worker test expected the full email address in a log line, so fixing the leak "broke" it (Ch. 20, F2).
- **Big-bang chapters.** Most chapters landed as one large commit straight to `main`, with no review; only Ch. 21's changes went through pull requests.

## Try (next time)

- When adding any CI step, **make it fail once on purpose** before trusting it.
- When a test fails after a fix, ask first: *does this test describe behaviour we still want?*
- Route all TaskFlow changes through pull requests, one story each (Definition of Done, `docs/planning/definition-of-done.md`).
